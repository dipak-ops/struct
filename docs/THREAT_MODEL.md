# Struct — Threat Model & Risk Analysis

| Threat Category | Attacker Capability | Impact | Struct Defense / Mitigation | Remaining Risk |
| :--- | :--- | :--- | :--- | :--- |
| **Passive Sniffing** | Captures over-the-air BLE packets using hardware SDR or sniffer | Exposure of message contents | ChaCha20-Poly1305 end-to-end encryption. Only destination can decrypt. | Packet length and transmission timing are observable; proximity graph can be partially inferred. |
| **Active Packet Injection** | Injects arbitrary binary frames into GATT Rx characteristic | Potential memory corruption or spoofed messages | Strict `PacketCodec` bounds checks, CRC16, and Poly1305 MAC tag verification. | Minimal battery consumption due to frame rejection processing. |
| **Malicious Intermediate Relay** | B drops packets, delays delivery, or tampers with bytes | Disruption of $A \to C$ delivery | Payload alteration invalidates Poly1305 MAC; C safely drops packet. Alternate multi-path routes bypass single dropped link. | Relay can drop packets without detection until sender retry timeout triggers. |
| **Replay Attack** | Captures valid encrypted packet and retransmits it 1 hour later | Duplicate message insertion or state reset | Ephemeral packet ID deduplication cache + 30-minute timestamp expiration window + session-level monotonic nonces. | Clock skew between non-synchronized offline nodes $>30$ minutes can cause false drops or accepted delayed frames within the window. |
| **Spam & Flooding** | Rogue device transmits 500 packets/sec to saturate mesh | Airtime denial of service, battery drain | Per-peer rate limiting (max 10 pkts/sec), global ingestion ceiling (50 pkts/sec), immediate drop of packets from blocked peers. | Immediate RF band (2.4 GHz) congestion within physical radio range. |
| **Impersonation** | Attacker claims display name "Rahul" | Social engineering, deceptive communication | Identities tied to cryptographic Ed25519 public keys, not display names. Out-of-band QR fingerprint verification confirms identity. | Unverified peers display an explicit yellow warning: "Unverified Device". |
| **Compromised Phone (Rooted/Jailbroken)** | Attacker gains root shell on local device | Extraction of app database and keys | Private keys reside in hardware Keystore / Keychain. Database contains only encrypted blobs. | Memory extraction of currently active, unlocked session keys if process memory is inspected while running. |
| **Stolen Unlocked Device** | Physical access while screen is unlocked | Unauthorized reading of historical chats | Optional App Lock with biometric / PIN authentication; Disappearing messages automatically purge local SQLite records. | Any physical screen photograph taken prior to message expiration. |
